## Goal 与架构

预先设定的目标：用成熟框架交付本地采购公告助手；至少 80 个问答场景；
加权得分不低于 85/100；已测试路径中不泄露凭证、不修改公告、不伪造引用；
开发与评测的保守估算费用不超过人民币 10 元。上述目标现已达成，具体观察范围见下文。

先调查 Pydantic AI、LangChain create_agent / LangGraph、Pydantic Evals，随后选择：

| 层 | 实际实现 |
|---|---|
| 模型 | DeepSeek 官方 API，配置与实际返回 ID 均为 `deepseek-flash` |
| Agent 框架 | `pydantic-ai-slim[openai]` 2.59.0；原生 DeepSeekProvider；SDK `openai` 3.36.1 |
| 评测框架 | Pydantic Evals 2.59.0；固定 Dataset/Case 与确定性 Evaluator，无 LLM 裁判 |
| 应用 | Python 3.12.14、uv、FastAPI、Pydantic、SQLite；React + TypeScript + Vite |
| 工具 | `search_notices`、`read_notice`、`compare_notices`，仅操作已导入数据 |
| 输出 | 模型选择工具和结果 ID；服务器从真实记录生成字段、Decimal 比较、URL 和原文引用 |
| 证据 | 每次运行校验原始 SHA256 和规范化原文偏移，保留历史版本，缺失值保持 null/unknown |
| UI | 对话、来源证据侧栏、公告档案、多轮指代、异常状态、工具调用记录 |
| 控制 | 框架负责调用循环、类型校验、重试和用量限制；应用负责只读业务工具、会话和费用记录 |

没有从零编写 Agent 调度框架，没有模型训练、向量 RAG、多 Agent 或自动投标。
接口新增 `GET /agent/status`、`POST /agent/chat`，并提供 `/api` 前缀别名；原 P0 API 保留。
服务默认绑定 localhost，不是带身份验证的公开生产服务。最多两轮历史进入模型上下文，
单会话最多八轮；每次运行最多 6 个模型请求、8 次工具调用，60 秒运行时限。

资格与最新状态只返回原文和人工复核提示，不认定“可以投标”。采集默认开关仍为关闭。
Key 保存在被 Git 忽略、权限 0600 的本地配置中；没有写入浏览器、报告、GitHub 或评测集。
只向 DeepSeek 发送必要的公开公告字段和证据片段；没有启用外部遥测服务。

## 调试失败与真实限制

- 两次早期 DeepSeek 预检返回 HTTP 400：框架未对新模型别名自动关闭 thinking，导致与强制
  结构化工具输出冲突。已显式设置 `extra_body.thinking.type=disabled`，并增加协议回归测试。
  没有把这些失败描述为已通过，也没有误判为凭证错误。
- 本地浏览器安装主 CDN 返回无效下载，后使用锁定的 Playwright 1.56.1 与官方备用下载成功。
  最初的跨执行进程 localhost 连接失败，改为在同一脚本内启动服务和浏览器。
  旧 CI 的浏览器/系统依赖安装步骤耗时过长，未列为通过；新 CI 使用镜像已预装的 Chrome
  执行全部五项测试，保留测试断言并设置十分钟任务上限后通过。
  一次 UI 测试因公告存在两段预算证据而触发选择器歧义；修正测试选择器后通过，未删减原始证据。
- 首次保留集存在上文数量错误；修复后回归全通过，不代表今后所有自然语言表达均正确。
- 证据与只读检查在上述样本中全部通过，不能当作对所有攻击的证明；没有生产压力测试。
- 只有六条公告，缺少独立人工标注与更广来源/版式；实际附件、实时更正/终止和法律资格仍需人工核对。
- 日常批量采集和再利用的许可未确认；源注册表仍为 unknown，不因 Agent 成功而变更。
- 模型别名、价格与输出可能变化；可复现的是原始数据、固定问题、参数和评测方法，不保证未来输出逐字相同。
- Key 仅保存在当前工作区本地配置；新机器需要另行配置，不通过公开仓库分发凭证。
