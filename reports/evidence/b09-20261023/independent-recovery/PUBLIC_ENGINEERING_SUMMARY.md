## 超载与费用检查内容

- 两个并发不同 key 在容量 1 时仅创建一个任务，另一个明确 429；同 key 在满容量下仍重放原任务，不重复解析、提交或写结果；同 key 不同输入返回 409。
- queued / running / waiting_review / interrupted / cancel_requested 均计入活跃容量，终态释放容量；审核等待释放计算槽，取消终态不能复活。
- 实际 ASGI 入口检查同 key 并发去重和异输入冲突；企业对话实际入口检查按用户限流。
- 本地 FunctionModel 模拟供应商 429，持久 attempt 保持 unknown，共享账本 reservation 保留；新 guard 重启后仍因预算或请求上限拒绝，不再次调用模拟供应商。错误正文不写入公开错误或持久 attempt。
- 旧 Demo / screening / durable attempts 共享既有累计账本；孤立预留、失败、取消、未知响应以及恢复确认均不释放已占费用。

停服务后生成 v4 成对业务 / DBOS 备份，包含 6 个文件；备份后真实新增材料、撤销授权、删除原材料、停用主体，然后删除自己的整个实例目录。备份位于该目录之外。从备份恢复到新目录后：

- 四份固定原文 / 附件 / 私有 blob / 规范文本 SHA256 一致；15 类不可变业务表的行数和内容摘要一致。可变安全投影明确隔离，不参与冒充原权限的等值比较。
- 两个业务 job 与两个 native root 被隔离 / 取消；已完成 calculation child 保留 SUCCESS 历史，不作为可运行任务复活。
- 登录表、对象 ACL、审核 assignment 清空，主体 fresh_until=0，审核 epoch 轮换，旧 outbox 冻结。Alice / Bob / admin 的旧 cookie 对材料、两种 job、审核详情与导出共 **15 次实际 HTTP 请求均为 401**，没有私有正文。

- 合成账本 booked ¥0.031、unknown reservation ¥0.5 原行与费用数值保留；它们是故障夹具，**不是真实支出**。
