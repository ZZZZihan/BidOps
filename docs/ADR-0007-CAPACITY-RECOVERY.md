# ADR-0007：容量、监测与恢复的保守裁决

状态：采用有界工程实现；目标环境容量、真实告警、完整恢复和数据库扩容裁决均待验，
对应 B 类门槛保持 BLOCKED。本文不报告当前全量测试或正式负载通过。

## 问题

当前运行时由单机 SQLite、单 ASGI worker、DBOS 原生工作流和一个资格计算槽组成。冻结
B09 要求 1 企业、20 账号、10 活跃 client、10,000 公告版本、50,000 包、200 材料，以及
两份活跃计算。脚本存在、单元夹具或更强开发机短测均不能证明该目标已经实现。

完整规模准备暴露两个真实边界：按 version 查包缺少匹配索引；完整候选超过普通
10,000,000-byte 保存通道。单纯增加等待时间不能修复第二个问题，也不应通过缩规模、
少存采购包、扩大所有私有正文上限或提高计算并发绕过目标。

## 决定

1. **保留 SQLite 和单 worker。** 不改变计算 Semaphore=1，不把最多 100 个业务活动任务/
   父工作流等待槽称为模型并发。manifest 明确 target=2、actual=1，该项如实 FAIL。待真实
   目标环境测量后，再决定是否另开含迁移、回滚和恢复验证的数据库/共享限流 PR；当前
   B09-07 不得 PASS。
2. **固定完整输入与分母。** 使用 capacity-v1 原文件 SHA256
   `bd82c7ab050a53610742515d4af082140f6fce5593b203cabaa4e847ffb4a170`，预热 300 秒、
   稳态 1,800 秒、2 次逻辑操作/秒和 78/18/2/2 混合比例。4,200 条预登记到达、全部失败、
   超时、429、晚到和缺失都保留；逻辑操作与额外鉴权/依赖 HTTP 分列。完整数值和判定见
   [CAPACITY-RECOVERY](CAPACITY-RECOVERY.md)。
3. **分开准备成本和稳态指标。** 测量前完整候选冻结的受控客户端等待为 300 秒，记录真实
   耗时和失败；稳态请求保持 10 秒、零重试。准备结果不得作为达标 P95 样本。失败后保留
   原目录，用新库、新输出重试，不能复用半准备数据或降低规模。
4. **修复规模路径，限制扩大范围。** 012 新增 `(version_id, package_id)` 索引；只给
   服务端完整构建且严格绑定来源/包件闭包的 candidate_batch 专用 ≤50,000,000-byte
   保存通道，普通结果/raw-output 仍为 ≤10,000,000 bytes。人工详情候选默认 20、最多
   100 一页，保留全量计数和固定 manifest hash。完整历史导出 ≤60,000,000 bytes，超限
   413，不静默截断。此项为新增 B09-08，原冻结规模与门槛不变。
5. **监测默认关闭，送达不作推断。** `BIDOPS_OPERATIONS_ENABLED=false`。可选进程内
   观察须新鲜且失败影响 ready；独立 watchdog 检测进程不可达，只输出本地告警与恢复
   JSONL。完成检查后才取观察时间，避免在途故障告警时间早于故障。每 I/O timeout 和
   分块 elapsed guard 不能宣称严格 wall-clock 强杀。缺实际企业接收端和发送授权时，
   B09-05 为 BLOCKED。
6. **以业务与授权恢复定义 RTO。** 继续使用停服务、同一独占锁下的 v4 typed bundle，
   绑定业务/DBOS 双库和私有文件。恢复登录失效、来源/任务隔离、review 新 epoch、
   assignment 撤销、outbox 冻结、调度暂停和共享费用对账屏障均不能省略。RPO≤24 小时、
   RTO≤30 分钟必须实际测量，RTO 终点含授权核验及获准业务可用；health 成功不是终点。

## 后果和回退

本机 FunctionModel、合成身份协议和完整合成数据 HTTP 运行只能标为 `local_engineering`，
模型等待与真实模型吞吐分列。没有真实来源/模型外呼、真实告警发送或生产部署。较强主机及
后台其他测试须披露，不能投射为目标 4 CPU / 8 GiB 主机的达标证据。

分页降低网络负担，但固定结果全文读取、hash、ACL 复核和导出仍有开销，必须计入测量，
不能因大正文通道通过结构检查就声称端到端 SLO 达标。超过 50 MB/60 MB 或缺失引用仍
明确拒绝，不能把上限扩大当作无限容量承诺。

012 为 additive 索引，保留旧 ID 和证据，不执行破坏性降级。升级前创建可恢复配套备份；
回退先停写，切换升级前镜像和 typed bundle。旧服务的 10 MB/未分页路径不保证能处理
新大批次，不能仅降镜像宣称兼容，也不能删除新历史使旧代码勉强启动。

B09-02 目标容量、B09-05 实际告警、B09-06 完整恢复和 B09-07 基础设施裁决未完成前保持
BLOCKED。工程标准的具体通过状态只由实际记录决定，不从本 ADR 推导；业务质量、真实
账号和具名人工验收继续按 B08/B10 独立门槛处理。
