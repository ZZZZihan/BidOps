# B01：企业初筛契约与独立评测协议 v1

本协议实现计划 B01-01～B01-07。它冻结可执行的业务对象、数据隔离、评分、
独立标注和人工对照规则，不表示真实公告上的 Agent 效果或企业验收已经通过。
实际执行记录见 `reports/b01-contracts-eval-20261023.md`。

## 契约与兼容

`bidops.screening.schemas` 独立于原 P0/demo 模型。它不新增 API、不改变数据库、
不启用 Agent，也不改变已有会话、历史成绩及费用记录。

- 资格五态：`satisfied`、`not_satisfied`、`information_insufficient`、
  `evidence_conflict`、`not_applicable`。执行完成不是资格满足，也不是人工批准。
- `AssessmentInputs` 固定公告、画像、材料、附件的对象／版本／SHA，以及 `as_of`。
  `EvidenceRef` 固定文本 SHA、引文、字符范围、定位版本及可选页码。
- 条件保留原文、硬门槛、采购包范围、AND/OR/NOT/例外逻辑树、有效期。
  `unless` 的两个操作数依次是主条件与例外；不在 B01 实现通用逻辑推理。
- 明确判断必须有双方证据。缺材料、未解决冲突、未知适用范围不得标成满足。
  有效期条件必须明确时区，企业证明覆盖所需时间；`as_of` 依据绑定输入时间。
- `ReviewCommand` 没有 actor 字段；真实人审服务须在 B06 从授权会话注入身份。
  `ReviewEvent.origin=test_fixture` 只能代表夹具，`server_authenticated` 的字段形状
  也不自行证明真实授权。B01 没有提供可伪造人审的 HTTP 入口。
- schema 接收现有模型实例时仍递归复验，防止可变列表绕过验证。

字符跨度与文本哈希在评分器的受控 oracle 上核验。真实文件字节、权限和当前版本
由 B02/B03 的服务负责，单靠一个合法的引用对象不能证明这些事实。

## 数据切分、抽样与金标

`eval_protocol.py` 把项目族、公告关联、版本链、全局采购包／附件 ID、原始／文本／
附件哈希构成关联组。组不能跨开发／回归与验收；验收集中给同组更换族 ID 也失败。
已知旧六公告按代码、原始 URL 和 SHA 排除，且排除沿关联传播。相同字节内容不能
通过换记录 ID 补足样本量。这里检测已登记关联和已知内容重复，不宣称发现未知的语义重复。

保留原 P1 门槛：30 份有使用依据的真实公告、3 类公告、2 种版式、20 个随机抽取且
独立人工标注的新项目族；历史与采集时未来截止各 10 份。未来公告的可得性例外必须
在冻结前记录可得数量与证据 SHA，不能看结果后豁免。

`stratified_family_random_v1` 先固定候选池哈希与 seed，按六风险分层和项目族进行确定性
随机抽样。同族多个包、版本不能冒充独立样本。六风险为硬条件不符、缺资质证明、
证据冲突、资格更正、终止和附件依赖，每层至少 3 个不同真实项目族。覆盖不足为 BLOCKED。
真实数据数量和独立金标数量分别计算；工程夹具不会补足任何真实数量。

每条真实独立标注都需要独立标注者和独立复核者；分歧另需仲裁人与明确结论。
开发／调试者、模型预标注、缺原文、无复核或未仲裁记录不能计入最终金标。
`critical=false` 不能关闭真实标注的复核要求。身份与盲态证明保存在受控位置，
公开仓库只保存无个人信息的引用标识。校验器审核记录完整性，不认证声明的真实性。

标注记录模板由 `AnnotationRecord.model_json_schema()` 导出，必填字段为
`record_id/family_id/source_sha256/input_sha256/gold_sha256/quality_unit_ids`；
另填写 `purpose=real_independent`、原文引用、标注／复核者 ID 与时间，分歧时填写仲裁字段。
人员记录使用 `Contributor`，具备独立性、实际人员及受控证明引用。
不要用虚构身份填充生产模板。金标的条件 ID、原文和逻辑结构必须在运行前规范化固定；
评分器采用精确结构比较，不依赖模型或 LLM 裁判替等价改写打分。

## 评分分母和错误分类

所有任务以事前登记的 `GoldTask` 为分母。失败、超时、取消、中断、缺失和非法输出
仍占质量单位，无法完成的单位不得算正确。预测保持原始 JSON 供检查，schema 拒绝
不会清除“无证明却满足”的严重主张。重复任务只用首条计主成绩，后续尝试仍进入
安全审计，且重复本身使协议 FAIL，不挑最好一次。

| 指标 | 计算及门槛 |
| --- | --- |
| 项目代码／原始链接 | 正确明确输出 / 应标已知字段，100%；明确输出精确率也为 100% |
| P1 截止日／预算单位 | 正确 / 全部明确输出 ≥95%；已知应评字段的非弃答覆盖 ≥85% |
| 其他 P1 字段 | 标题、采购人、预算、公告类别、资格片段逐字段报告精确率、召回、覆盖、弃答及错误 ID；不藏入总分 |
| 候选召回 | 展示的应入候选 / 全批应入候选 ≥95%；采购包与项目族分别报告 |
| 硬条件召回 | 正确保留原文、范围与逻辑结构的适用硬条件 / 全部适用硬条件 ≥95% |
| 明确判断错误 | 错状态、改条件、缺支持或非法任务中的明确判断 / 全部明确判断 ≤5%；条件和采购包分别报告 |
| 可判断覆盖 | 给出明确结论的金标可判断条件 / 全部金标可判断条件 ≥85% |
| 引用可解析 | 可读、版本和文本范围完全匹配的引用 / 全部引用 100%；条件定义和结果中的引用均计算 |
| 证据支持 | 被独立金标支持的判断 / 所有已输出五态判断 ≥98%；冲突需其指定的矛盾证据，信息不足需公告依据及标注的缺失项 |
| 严重错误 | 硬不符／缺证明／冲突被判满足、硬否决仍正向推荐、终止仍推荐，任一例 FAIL；分别公布类别分母 |
| 版本错误 | 未披露的失效证据用于当前结论，任一例 FAIL；披露失效也不让旧证据支持当前满足结论 |

明确判断和冲突的支持依据是独立复核的可替代充分证据组合 `support_bundles`，
不是模型自报 support=true。信息不足没有企业证明时不得虚构双侧证据，需匹配金标
冻结的 `missing_items`。声明“冲突”但引用真实而无关的材料仍然错误。
历史评估须显式设置 `scope=historical`，当前评估不自动接受旧版本。

所有指标给分子、分母、值及失败 ID；必需零分母为 JSON `null`（N/A）和 BLOCKED。
信息不足／冲突覆盖单独披露；三个严重硬条件类别及终止缺样本同样 BLOCKED。
候选、条件与全部任务分母不是从输出成功子集重建。版本错误与严重错误不能被平均分抵消。
全弃答不能满足可判断覆盖。总体质量只作为共同质量单位计数，不能代替逐项门槛。

金额必须是有限、非负 Decimal 字符串和显式币种／单位，元与万元以精确十进制比较；
单位字段仍按其原始单位单独计分。截止时间按带时区的同一时刻比较。未知值不是 0，
猜测未知值计错误；未知正确弃答另报，不补充“已知字段精确率”的分子。

## 人工对照

使用 `TrialPlan`、`TrialAssignment`、`TrialObservation` 模板。在首题开始前固定
完整输入 SHA、金标 SHA、交付要求 SHA、质量单位、时限、起止操作、随机 seed 和顺序。
每题两种方式必须有相同输入、交付要求、质量单位及时限；由不同人执行。
至少 10 个不同项目族、2 名真实独立使用者，顺序平衡。操作者不得看过对应金标、
参与其标注或先做过同题；同操作者在计划内重复项目族或输入也会被拒绝。

质量比较使用全部预登记任务和共同单位，未完成单位计未正确完成；严重错误为零，
辅助组总正确率不得低于人工组。时长由真实起止时间计算，必须大于零，活动和等待另报。
仅当全部任务完成且符合时限时，检验 `median(1 - assisted/manual) >= 0.20`。
任何失败、超时、中断或缺失使节时门槛 FAIL，并保留原因和停止时间。
完成子集的中位数只作诊断，不能用于取代全任务结论。

## 冻结、运行与复现

`evals/enterprise-v1/protocol.json` 固定上述门槛，`freeze.json` 固定执行源码、
锁文件及工程夹具。调用方必须事前保存清单 SHA；不能在结果不好时用新自算 SHA
替换旧 pin。清单被替换、源码或输入改变、重复路径、目录穿越均失败。
CI 与本 PR 明确保存同一 pin。B08 的真实候选池、金标、画像、提示与人员计划需另行
冻结；本次固定样例不证明已经具备那些输入。

离线命令见 `evals/enterprise-v1/README.md`。它只接受明确的工程夹具，执行 Pydantic
Evals 自定义 evaluator 和全任务聚合器；实际模型为 null、调用／tokens／费用为零，
`agent_score=null`，业务验收始终 BLOCKED。无 API key、真实来源或服务实例也能运行。
它检查执行根目录与冻结源码一致，以及 Pydantic/Pydantic AI/Pydantic Evals 的实际
安装版本与锁文件一致；不宣称验证每个第三方 wheel 的字节供应链。

结果记录真实 HEAD、数据／画像 SHA、提示与 scorer 版本、实际模型及参数、用量、
费用和 dirty 状态。未提交代码的结果不能冒充对应 HEAD 已验证。输出只含受控 ID、
计数与错误类别，不复制材料正文；已有报告采用排他创建，不自动覆盖失败结果。

沿用锁定的 Pydantic Evals 2.59.0 自定义 `Evaluator` 与 `Dataset.evaluate`，
没有新增第三方依赖、LLM 裁判或编排器。依据为[官方自定义 evaluator 文档](https://pydantic.dev/docs/ai/evals/evaluators/custom/)
以及本地锁定版本的实际运行测试。

首次盲测及所有失败必须保留；根据盲测答案修复后，该集合转回归，新独立结论使用新盲测。
累计模型预算人民币 10 元不重置，未确定费用继续预留。B01 不产生模型或采集费用。
