# LLM 工程原则在 BidOps 的首轮试点

2026-10-26。范围是现有采购公告问答，基于 `feature/demo-workflow`，依赖 PR #29。
本轮使用一个独立 PR，落实 prompt 管理、运行追踪和可重复的离线回归。
不调整 prompt 文案、供应商、模型、费用规则、资格核对逻辑或数据库结构。

## 已落地的约定

- 静态指令唯一来源是 `backend/bidops/agent_demo/prompts.py`，名称为
  `bidops-notice-qa`，初始登记版本为 `notice-qa-v1`。`repository-maintainers`
  表示仓库维护角色，不代表某位个人或 GitHub 团队已经接受责任。
- 迁移前后 UTF-8 字节哈希保持
  `cd2abb4a635a9523a92fa259491feb2707bbea9e9b728d622adb9c3babad149e`。
  `runtime.INSTRUCTIONS` 保留原导入接口。这个哈希只覆盖静态指令；动态参考时间
  通过既有 `as_of` 表达，用户问题、历史和工具结果不属于该哈希。
- 每轮成功回执增加 `prompt` 对象。旧持久化回执没有这个字段时仍可重放，并保持
  `null`；不会补写当前身份或重新消费模型费用。
- 已通过数据与预算预检的执行在底层 `audit_events` 留下 prompt 名称、版本、owner、
  哈希、配置模型、耗时和使用量。成功记录实际返回的模型名；失败时无法取得运行结果，
  返回模型身份保持 `null`，保留现有费用预留。新字段不记录问题、原始材料、完整指令、
  凭据或提供商异常正文。此处是每轮运行汇总，尚非逐个模型请求的完整追踪。
- `evals/llm-pilot-v1.json` 固定 prompt、模型参数、执行上限和历史评估输入的指纹。
  修改这些内容后旧清单会使检查失败；仍执行整组回归，保留变更后的失败报告供复核。
  通过实现评审后才能有意更新清单；改 prompt 内容应同时修改版本。
- 清单还固定试点用例 ID 集合，防止只跑部分用例却报告通过。入口清除继承的 pytest
  筛选参数，CI 的完整后端模式继续执行全部后端用例。

底层运行审计与企业管理员 `/api/audit` 的 `enterprise_audit` 是不同的现有路径。
本轮不宣称管理员列表已经展示新增字段。数据完整性、空库和预算准入拒绝发生在执行前，
也不属于这里的模型执行审计。

## 重复运行

沿用项目锁定的依赖，包括 `requirements/durable.lock` 和 `attachments.lock`。
从仓库根目录执行，输出路径必须是新文件：

```bash
uv run --frozen --no-sync python scripts/llm_pilot_check.py \
  --output data/artifacts/llm-pilot/local-001.json
```

检查复用现有公告工具/引用/结构化输出、评分器正负例、共享预算兼容测试，并加入
prompt 审计、历史回执和报告失败路径。测试使用 UNIT 片段、模型替身、内存 HTTP
协议响应及临时数据库；`tests/conftest.py` 阻止真实 HTTP 和真实模型调用。
程序不读取密钥、不加载真实公告库，也不运行 `demo_eval.py --execute`。

CI 使用 `--full-suite` 执行完整后端测试，同时生成这份报告，避免再重复运行一遍试点。
除原有“未构建前端时跳过实际预览 CLI”检查外，跳过、失败、中断、未收集到测试或
清单不一致都会阻止通过。原有前端和容器 job 继续保留。报告作为 Actions artifact
保存；既有 B01 scorer 与冻结 pin 保持原样。

报告包含提交 SHA、是否有未提交改动、相关文件与锁文件哈希、完整用例状态、运行命令、
测试退出码和配置身份。旧报告不能被覆盖；失败也会保存报告。
`execution_kind=offline_contract`、`actual_provider_calls=0`、`agent_score=null`，
`business_acceptance=BLOCKED`，明确区分工程检查和业务效果。

## 当前证据边界与后续使用

现有 96 场景 / 105 条问题由实现者围绕六份真实公告编写，并非真实用户请求日志，
也不是独立人工金标。本轮只核对这些文件指纹，没有执行或重打分这 96 个场景。
既有首次 held-out 71/72 与后来回归 72/72 的记录不因此改变。

`deepseek-flash` 是项目配置的模型别名，本清单明确标为未锁定不可变模型版本；
收到模型名也不能证明供应商后端绝不变化。真实调用效果、延迟和费用仍需实际记录。

后续在此项目使用这套原则时，优先保持已有结构化输出、窄工具、证据绑定、失败关闭、
小上下文、硬预算及人工复核，再针对观察到的失败添加回归案例。
真实用户输入需经适当脱敏后单独标注来源，不把开发者编写的问题包装成用户数据。
真实模型回归沿用既有评估协议、合法原始材料与同一费用账本，在明确的调用范围和
预算授权内执行。离线替身不理解 prompt 语义，不能代替该步骤。

薄供应商适配、混合检索/重排、缓存、模型路由、流式展示、反馈采集和微调属于后续
按实际需求选择的措施，本轮没有新增这些能力，也不以离线检查代替企业验收、
历史资产恢复、合并或部署。
