# 企业画像、材料与授权

B03 提供单企业内部的版本化画像和私有材料。企业模式未配置时 `/api/company/*`
返回 404；没有匿名材料入口。此文描述代码行为，真实公司材料、Keycloak、HTTPS 和
独立用户验收仍需 B10，不能用协议夹具代替。

## 身份与对象权限

请求身份来自原有 Authlib OIDC 登录。当前主体必须 active，可信角色快照尚未过期；
细节与 Keycloak 适配范围见 [ADR-0004](ADR-0004-IDENTITY-REVOCATION.md)。
默认快照期限 240 秒，到期后重新 SSO；本地停用、对象撤权和已验证的注销事件立即影响
下一次授权检查。旧登录 Cookie 或旧任务上下文不缓存对象权限。

| 操作 | 必需主体权限 | 必需对象动作 |
| --- | --- | --- |
| 列表、详情、检索、引用、下载、导出 | `catalog:read` | `read` |
| 创建画像或材料 | `agent:use` | 创建后由服务端授予创建者 |
| 修改画像或材料 | `agent:use` | `write` |
| 授予、撤销对象权限 | `agent:use` | `grant` |
| 删除对象 | `agent:use` | `delete` |
| 旧备份恢复后重新授权 | 管理员权限 | 显式指定对象、主体与动作 |

管理员没有隐含正文读取权。授予对象动作也不能绕过主体角色：例如 analyst 降级成
viewer 后，已有 write/grant/delete 动作不再允许修改。未授权对象不可见，详情返回
拒绝，不泄露标题、原文或文件路径。画像读取还会在返回前，在同一授权事务中重查全部
来源材料。创建者、角色、文件路径不接受模型或客户端自行指定。

`ToolContext(owner_id)` 只能由后端可信身份生成。B04/B05/B06 必须在工具执行、恢复、
导出和结果释放前调用共享授权服务；`require_inputs` 核验固定版本/哈希和派生来源闭包。
这份接口合同不代表后续任务、审核入口已经实现。

## 固定版本与证据

画像每次修改生成新 revision，更新请求必须携带 `expected_version`，旧版本竞争返回
409。事实区分 `self_reported / document_supported / unknown / conflicting`，有材料
支持的事实必须带企业材料证据。自报或无文件不能变成已证明的资格。

材料更新使用 `If-Match`。原文 blob 与规范化文本以受控 revision 文件名保存在
`data_dir/private/company/`，与公告 raw、公共清单及公告导出隔离。证据固定材料版本、
原文和文本 SHA256、`normalized_text_v2` 字符范围与精确引用 ID；本实现不声称有 PDF
页码。引用读取会重新检查原始字节、文本、范围和当前权限。

资格有效期是证据业务时间，与数据留存期限不同。资格检查以请求中的带时区
`required_at` 为准；缺日期、缺证据或材料冲突均保留未知/冲突。截止时点的精确有效期
判断来自材料证据，不能仅根据企业自报字段判满足。

## 文件与入口

当前仅接受 UTF-8 纯文本及 HTML；最多 2 MiB，规范化文本最多 200,000 字符。
HTML 限制 10,000 节点、64 层深度和每节点 100 个属性，并拒绝无效闭合结构。
伪扩展名、格式不符、路径穿越、二进制、归档和未实现的 PDF/Office/OCR 均拒绝，
不会执行文件、解压未知内容或把失败当作空白成功。材料上传路由先鉴权再有界读取流；
只有精确上传路径使用 2 MiB 边界，其余请求仍适用原 16 KiB 全局限制。

主要入口（均为 `/api/company` 下的受保护接口）：

- `/profiles`：分页列表、创建；`/profiles/{id}`：固定版本详情和乐观锁更新。
- `/profiles/{id}/versions/{version}/facts/{fact}/validity`：指定资格时点核对。
- `/materials`：分页列表、上传；`/materials/search`：授权范围内检索。
- `/materials/{id}`：元数据、固定版本正文及更新；`/download`、`/export`、
  `/citations` 提供受保护下载、导出和引用。
- 对象授权、撤权、删除与恢复隔离后的显式重新授权由同一共享服务执行。

浏览器界面提供画像/材料版本、来源说明、引用和对象授权。发生 401/403/404 时清除
正文、画像草稿、引用及搜索缓存。刷新时重查已选固定版本和全部引用来源，不能只依赖
列表请求成功；对象不在当前分页中也不等于无权。409 保留用户草稿，不自动覆盖服务端。

## 留存与完整恢复

默认私有对象留存 30 天。到期时授权层立即拒绝，随后启动/每小时维护及
`bidops-enterprise prune` 删除私有 blob、文本和依赖画像正文，只保留必要版本、
哈希和删除标记。清理失败会保留失败状态并重试，不把旧正文重新开放。

备份前停止企业进程；备份与服务使用同一 SingleWorker 文件锁，防止复制过程中写入。
备份包含数据库及被引用的公告 raw、B02 公告附件、私有 blob/文本；每个文件和数据库
引用闭包都核对 SHA256，缺文件、多余私有文件、路径穿越或损坏均拒绝恢复。

新备份 manifest 带创建和到期时刻，默认窗口 7 天、最多 30 天；恢复拒绝过期包。
此窗口限制本程序的恢复许可，不能撤回已复制的字节。运维方须按相同政策清理备份介质
与副本；本 PR 不声称自动删除离线副本。新格式为 v3；旧 v1 和 B02 的无期限 v2
仅在不含私有对象时接受。此前 B03 的带期限 v2 也继续验证期限后接受。

恢复先在临时目录验证完整闭包，再清除登录、OAuth state、旧身份快照及全部对象 ACL，
将所有私有对象置于恢复隔离，清除当前已到期正文，最后发布恢复目录。失败不发布部分
可用实例。即使备份后发生的停用、撤权或删除记录丢失，旧授权也不会复活；重新登录
不会解开对象隔离。必须由管理员结合独立保存的最新授权/删除依据逐对象重新授权。
无法确认最新权限时保持关闭；不得凭备份中的旧授权自行恢复。

运行示例（路径均由运维提供，不能指向公开仓库）：

```sh
uv run --frozen --no-sync bidops-enterprise backup --output /controlled/backup --retention-days 7
uv run --frozen --no-sync bidops-enterprise restore --input /controlled/backup --output /controlled/restored
uv run --frozen --no-sync bidops-enterprise prune
```

具体命令参数以 `--help` 为准，数据库和数据目录由既有环境配置指定。升级前在停止写入
时保存完整备份；005/006 是增量迁移，旧公告和会话记录不覆写，旧登录需要重新 SSO。
回退代码时保留新库/私有文件隔离副本，使用升级前完整备份恢复到新目录再运行旧服务，
不要删列或清表来强行降级，也不要将私有材料复制到旧公共公告目录。

实际工程结果、输入版本及逐项状态见本 PR 的验收报告。任何测试成功都不代表真实企业
授权资料已导入、真实 IdP 已配置或人工业务验收通过。
