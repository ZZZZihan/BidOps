  [已有数据契约](DATA-CONTRACT.md)、[已有 P1 门槛](EXPERIMENT-PLAN.md)。

  [独立数据验收 Issue #9](https://github.com/ZZZZihan/BidOps/issues/9)。
- 基线仍为 6 份公告 / 15 个采购包；公告当前状态为 unknown；来源持续获取许可未确认。

继续使用 FastAPI、React/TypeScript、Authlib、Pydantic AI / Pydantic Evals 与 DeepSeek。

## 2. 验收记录规范

### 2.1 每条任务的必填记录

本文件每一行验收项都有唯一 ID。实现 PR 的变更清单必须逐项映射到这些 ID；
新增任务必须新增验收项，不能只增加一个笼统的“测试通过”。

| 必填字段 | 要求 |
| --- | --- |
| AC-ID | 使用 Bxx-yy；跨 PR 的共同约束使用 G-yy |
| 被测对象 | 完整代码 commit、依赖锁文件；涉及模型时记录实际返回模型标识、提示版本与运行参数 |
| 输入与操作 | 样本/夹具 ID、画像/公告/材料版本、as_of、前置权限、执行命令或可复查操作步骤 |
| 预期结果 | 数值阈值、状态转换、错误码或不变量，必须可判断是否满足 |
| 实际结果 | 原始计数、观察值、失败明细；不能直接抄预期结果 |
| 证据 | CI run/job、脱敏报告路径、截图或操作录像、数据清单哈希；敏感原文留在受控位置 |
| 结论 | NOT_RUN / BLOCKED / PASS / FAIL；未执行用 NOT_RUN，明确缺输入用 BLOCKED |
| 责任与阻塞 | 执行者/复核者、执行时间、缺失输入及其阻塞的里程碑 |

下文所有验收项初始状态都是 **NOT_RUN**；涉及缺少的来源许可、独立人工、企业材料、IdP、
HTTPS 或目标机器时，在实施 PR 中登记为 **BLOCKED**。代码模拟、人工实测、真实模型实测必须分别标记。

历史可追溯须遵守授权和留存：仍有权且在留存期内的原文可复查；到期或删除后保留必要哈希、
版本及删除标记，并明确显示原文已不可用，不能为了“回放”重新开放或重建已删除私有材料。
RPO允许业务记录丢失窗口，不允许把无法确认的旧授权重新视为有效。

表中 **C** 是代码合并门槛；**B** 是业务/真实环境门槛。
只有 C 全部通过且有对应证据，才可请求实现 PR 的代码合并。
B 未通过时，可以交付默认关闭的基础设施，但必须保留该 PR 的“业务验收未完成”状态及阻塞项。
B08/B10 可以提交真实失败报告；报告合入不改变业务验收失败或阻塞的结论。

### 2.2 所有实现 PR 的共同合并门槛

| ID | 验收输入与操作 | 通过标准 | 必交证据 |
| --- | --- | --- | --- |
| G-01 | 对照 PR diff 与任务清单逐项检查 | 每项新增/修改行为都映射到至少一个 AC-ID；每个 ID 有执行方式、实际结果与证据；C 项无 NOT_RUN/BLOCKED/FAIL | PR 描述中的逐项矩阵 |
| G-02 | 在该 PR 待合并提交运行相关测试；基线代码受影响时运行完整后端套件、lint；前端变化运行构建及相关浏览器流程 | 没有新增失败；不得删断言、跳过失败或降低门槛取得通过；记录实际测试数量，不固定要求永远是 189/12 | commit、环境、完整命令、退出码与 CI 日志 |
| G-03 | 对新增持久化执行旧库迁移、重复迁移及恢复演练；无迁移则核对 diff | 旧数据、已有会话与证据仍可读；重复迁移不损坏；回退步骤可执行；无迁移时提供无 schema 变更的依据 | 迁移前后计数/哈希、恢复报告，或 diff 说明 |
| G-04 | 对所有新读写入口检查身份、权限、日志和公开文件 | 授权在后端执行；默认拒绝越权；凭证、私有原文、个人信息不进入公开仓库或普通日志；列出所涉 C 验收 ID | 权限负向测试、脱敏样例、diff 检查 |
| G-05 | 冻结并复查新增第三方组件的官方依据、版本和部署要求 | 复用现有框架；持久执行等通用基础设施有官方文档和兼容性证据；无新增依赖时明确记录 | ADR 或 PR 技术说明、锁文件、兼容性检查 |
| G-06 | 每条真实模型/来源请求执行前核对数据权限和预算；本 PR 无外部调用时核查执行日志 | 运行方式、许可范围、预计调用上限可核验；成本不超过剩余累计预算；未运行不得声称真实模型或采集已通过 | 执行参数、用量账本或无外部调用说明 |
| G-07 | 将实际验收报告与代码、数据、画像、提示版本逐一比对 | 报告对应本次版本；修改后只保留为历史的结果不能冒充新提交结果；FAIL/BLOCKED 不改写成 PASS | 报告清单及版本对照 |
| G-08 | 在旧行为与新行为切换/关闭时运行受影响的业务路径 | 能按本 PR 的回退说明恢复原服务；已经形成的审核及证据不丢失、不被覆盖；外部依赖未就绪时明确不可用 | 回退步骤及对应检查记录 |

测试入口沿用现有 uv run pytest -q、uv run ruff check .、uv run ruff format --check .、
npm run build --prefix frontend 和 npm run test:e2e --prefix frontend。
每个实现 PR 必须再提供本 PR 新增测试的精确命令；下文“证据文件”均是待实施交付物，不是声称它们已存在。

## 4. B01 — 业务契约与独立评测协议

建议标题：test(eval): freeze screening contracts and independent acceptance protocol  
建议分支：codex/b01-screening-contracts-eval  
主要落点：docs/EXPERIMENT-PLAN.md、evals/、scripts/demo_eval.py、
backend/bidops/agent_demo/evaluation.py；新增业务 schema 与评分器测试。

冻结三类独立状态：资格结论、人工决定、任务执行状态。
资格结论至少包括满足、不满足、信息不足、证据冲突、不适用；人工决定由真实授权人员产生。
字段包含项目/采购包、条件原文、AND/OR/例外/时效、是否硬门槛、公告证据、企业事实证据与版本。

| ID/类型 | 验收输入与操作 | 通过标准 | 必交证据 |
| --- | --- | --- | --- |
| B01-01 C | 校验满足/不满足/缺材料/冲突/不适用等合法对象，以及缺版本、缺证据、非法状态对象 | 合法对象通过；每种非法对象被 schema 拒绝或明确置为信息不足；资格结论不能充当人工批准 | schema、正负样例及验证日志 |
| B01-02 C | 将旧六公告、同项目不同包、不同更正版本、重复内容分别放入开发与验收集 | 旧六公告只进入开发/回归；项目族、版本链、包和附件不跨集合；已知内容重复触发拒绝；正常独立切分通过 | 切分清单哈希、泄漏检测测试 |
| B01-03 C | 对照既有P1门槛逐项核查，输入数量/类别/关键风险覆盖不足的清单 | 保留至少30真实公告、至少3公告类别、至少2版式、20+随机选取独立人工金标；历史与采集时未来截止公告各10，遵循原“可得时”约束；按第14节关键分层校验，缺覆盖为BLOCKED | 协议diff、抽样规范、数据门槛校验输出 |

| B01-06 C | 检查独立标注与人工对照方案；尝试缺标注者、缺原文、缺仲裁的记录 | 协议要求真实独立标注、关键条款复核、分歧仲裁；不合格金标不得进入最终评测；人工与辅助组使用相同输入与交付要求并平衡顺序 | 标注模板、抽样/分组方案、记录校验 |
| B01-07 C | 在看到新验收结果前冻结本文件第14节目标；故意篡改冻结清单/评分版本 | 评测能发现冻结版本不匹配；结果中列代码、数据、画像、模型、提示、评分器版本；固定评分器样例不计作 Agent 成绩 | 冻结 manifest、版本验证测试 |

## 14. 新业务评测指标与拟冻结门槛

以下是本轮有限试用的**设计目标**，尚无实测结果。
B01 在看到最终盲测答案前冻结；任何目标修订保留原版与理由。
既有 P1 指标为必须继承的底线，不能被新指标或加权总分抵消。

| 指标 | 分子 / 分母或定义 | 有限试用门槛 |
| --- | --- | --- |
| P1溯源 | 可核验项目代码与原始链接 / 应标记录 | 100%；沿用原P1 |
| P1关键字段 | 正确明确输出 / 全部明确输出；非弃答字段 / 应评字段 | 截止日、预算单位精确率≥95%且覆盖率≥85%；沿用原P1 |
| 候选召回 | 正确展示的应入候选项目 / 全批次应入候选项目 | ≥95%；不能只评输出的项目 |
| 硬性资格条件召回 | 已正确识别的适用硬条件 / 全部适用硬条件 | ≥95%；遗漏率≤5%，AND/OR结构错误计错 |
| 明确判断错误率 | 错误的确定性资格判断 / 全部确定性资格判断 | ≤5%；按采购包与条件分别报告 |
| 可判断条件覆盖 | 对金标可判断条件给出确定结论的数量 / 金标可判断条件总量 | ≥85%；真实缺证据/冲突另列，不要求猜测 |
| 引用可解析率 | 可解析到有权读取的确定版本及原文的引用 / 全部引用 | 100%；不存在/篡改/越权引用是阻塞 |
| 证据支持正确率 | 两侧证据确实支持该主张的判断项 / 被复核的需证据判断项 | ≥98%；有效链接不等于支持结论 |
| 严重错误放行 | 冻结金标及所提供证据可知的适用硬条件“不满足”被结构化判为“满足”，或硬条件缺证据/冲突被判满足，或已知终止仍被正向推荐 | 任何1例即FAIL；不依赖页面有无“通过”字样；漏掉硬性否决后给正向建议同样计错；披露类别分母 |
| 版本错误 | 用已被更正的旧证据作当前判断且未揭示失效 | 样本内观察到任何1例即FAIL |
| 审核后质量 | 在相同预登记任务和共同金标单位上比较人工最终结果，未完成单位计为未正确完成 | 严重错误0；总正确率不低于同批人工基线；全部失败/超时保留在分母；分别公开计数 |
| 审核耗时 | median_i(1−A_i/H_i)，A与H为各配对辅助/人工总耗时且均>0 | 至少10个项目族的配对；中位节时≥20%；预登记时限，任一失败/超时即该门槛FAIL，不剔除；活动/等待时间另报 |
| 完成率与成本 | 全部预登记任务含失败、中断、重试和未知费用 | 完整披露；无隐藏失败；执行不突破剩余模型预算 |

必需指标分母为0时记N/A并将对应门槛设为BLOCKED，不能判PASS。最终盲测须覆盖：硬条件不符、
缺资质证明、证据冲突、资格更正、终止、附件依赖六个关键分层，每层至少3个不同真实项目族。
分层之间可以重叠，各层分别计数；真实覆盖不足保持BLOCKED，合成案例不能补足独立真实数量。
人工对照在首轮计时前冻结每题时间上限、起止操作、质量计分单位与操作者盲态；
未完成/超时任务按未正确完成进入全任务质量分母，并令节时目标FAIL，保留实际停止时间与失败原因。
小样本未观察到错误不等于总体错误率为零；按项目族报告样本量与不确定性。
固定夹具、合成资料、同数据改写题、LLM裁判得分不能替代独立真实结果。
如果真实对照未显示节时，保留结果并把“已证明节时”判为未通过，不事后换一个更有利指标。

## 16. 实现 PR 提交模板

每个实现 PR 的描述应包含：

1. 关联计划编号、父Issue、前置PR实际链接和完整base/head commit。
2. 问题、修改后的行为、代码范围和数据迁移。
3. 每项改动 → AC-ID → 测试/操作 → 实际结果 → 证据链接 → C/B状态。

5. 回退步骤、模型/数据调用预算与实际用量。
6. 本PR“代码可合并”和“业务验收通过”的两个独立结论。

某个实现PR确实过大时，可以按此表的AC-ID拆成子PR，并将实际依赖写回本文件。
