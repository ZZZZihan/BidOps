# BidOps MyGo 桌面入口

这个目录使用 MyGo `v0.6.4` 为现有 BidOps 网页提供独立桌面窗口。公告档案、Agent 助手、企业资料、完整流程、任务和人工复核继续使用原有 React 页面与 Python API。这里没有第二套业务界面、接口代理或数据库。

## 启动

需要 Go `1.27.3` 或更新版本。`go.mod` 固定 MyGo 版本，CLI 也由 Go tool 依赖固定，不需要全局安装。

先在仓库根目录按 [本机完整业务流程文档](../docs/LOCAL-WORKFLOW-DEMO.md) 构建前端，并使用既有数据目录启动服务。桌面入口不启动后端，不选择数据目录，不读取密钥，也不启用真实模型。已有费用、数据与调用授权继续由原服务管理。

然后在本目录运行：

```bash
go tool mygo dev
```

默认连接 `http://127.0.0.1:8765/`。如果原服务使用其他端口，可单次设置：

```bash
BIDOPS_DESKTOP_URL=http://127.0.0.1:8876/ go tool mygo dev
```

直接运行二进制时也可传 `-url http://127.0.0.1:8876/`。仅接受带明确端口的 HTTP `127.0.0.1` 根地址，不接受 `localhost`、远程主机、URL 登录信息、其他路径、查询或片段。本机流程服务严格校验 Host，所以桌面与服务必须使用同一个地址和端口。

窗口先显示内置连接页，首次尝试一次连接。服务未启动、页面未构建或加载失败时会显示状态与“重新连接”。连接只读取根 HTML，一次请求、最多三秒，不调用业务 API、不携带 Cookie、不使用环境代理、不跟随重定向。页面标题必须包含 `BidOps`，避免误打开被其他应用占用的端口。

进入工作台后，网页直接来自原 HTTP 服务。`/api`、Cookie、CSRF、登录和回调保持同源。浏览器和桌面各自保留 WebView/浏览器自己的登录状态；这不代表两个客户端共享会话。接口断开仍由原业务页提示，桌面不会自动重放提交。通过菜单“工作台 → 连接状态与重试”（`Cmd/Ctrl+Shift+R`）可回到连接页，再明确重试。

仅在同一服务 origin、该服务生成的 Blob URL 与内置连接页内导航，因而本机流程登录回调仍留在窗口中。用户点击的外部 HTTP(S) 公告链接交给系统浏览器；其他端口、私网地址、非网页协议及自动外部跳转不作为桌面工作区打开。该入口面向本机流程，不声明完成外部企业 IdP/SSO 的桌面适配。

现有审核包导出生成的 Blob，以及本机服务提供的附件，都使用系统“保存工作台文件”窗口选择位置。取消保存不会写入文件，也不显示失败或成功提示。原生下载完成后才显示“文件已保存”和实际路径；选择位置失败或下载中断会显示错误，提示不会包含原始下载 URL、业务内容或底层服务错误。中断可能留下未完成文件，须重新导出，不能视为完整审核包。其他来源的下载会被拒绝。

没有增加 `TrustedOrigins`。内置连接页可调用有限的连接状态与重试方法，正式构建的业务 HTTP 页面没有额外的 Go 调用权限。MyGo 开发构建自身会默认信任 loopback 开发页，应只连接可信的本机服务。

## 构建

在本目录执行：

```bash
go tool mygo build -skip-dmg -skip-notarize
```

macOS 产物是 `build/darwin-arm64/BidOps.app`（Intel Mac 为 `darwin-amd64`）。内置连接页随 Go 二进制嵌入，因此没有前端构建依赖；业务网页依然由外部 Python 服务提供。此命令只做本机 ad-hoc 签名，不公证、不上传、不安装。跨机器分发与其他系统运行需分别验证。

`.mygo/` 和 `build/` 是本机产物，不提交仓库。构建不会打包任何业务数据或密钥。

## 检查与验收边界

```bash
CGO_ENABLED=0 go test ./...
CGO_ENABLED=0 go vet ./...
```

Go 测试使用 `httptest` 的临时 loopback 服务，覆盖服务地址限制、同源登录路径、根 GET、无凭据/代理、错误状态、错误页面、重定向拒绝、超时、连接拒绝与明确重试后的恢复。下载测试覆盖同源 Blob/附件、拒绝其他来源、取消与迟到回调、保存窗口错误、真实完成回调前不报成功，以及失败提示脱敏。测试不运行 Python，不访问真实数据库或费用账本，不调用模型。

2026-10-26 的本机检查中，`gofmt`、上述 Go test/vet，以及 `go tool mygo build -skip-dmg -skip-notarize` 均通过；MyGo CLI 报告版本 `0.6.4`，生成 macOS arm64、ad-hoc 签名的 `BidOps.app`，约 10.2 MB。

另用该 macOS arm64 应用的真实 WKWebView，配合临时、无业务数据的 loopback HTTP 服务完成了以下烟测：

- 服务返回 HTTP 503 时显示内置连接页；服务恢复后，点击“重新连接”进入原 HTTP 页面。
- HttpOnly/SameSite=Lax Cookie 随页面的同源 `/api/auth/me` 请求发送；模拟登录的同源 302 回调仍在桌面窗口中。
- 服务停止后访问同源新页面，自动回到并绘制浅蓝白连接页；不会停留在空白画面。此路径也在加入下载处理后的构建中复测通过。
- 模拟审核包的同源 Blob 打开系统保存窗口；取消后没有结果弹窗，指定的临时目标没有产生文件。
- 选择临时目录后，真实落盘 JSON 为 55 字节，解析结果与指定的模拟内容完全一致；完成提示显示了同一实际路径。
- 服务故意截断附件响应后，仅显示“文件未能保存完成”，没有成功提示；临时目录留下了未完成文件，与错误说明一致。
- 临时 HTTP 服务直接提供本次 `frontend/dist`，仅模拟五个只读 API 的身份、禁用模型与空公告状态。实际在 MyGo 窗口打开浅蓝 Agent 首页并切换公告档案；服务日志只有 9 次 GET。停止服务后重新载入，自动回到内置连接页。三张原生窗口截图与前端构建指纹保存在本机忽略目录 `.mygo/verification/`，标注为离线 UI 协议场景。
- 另一临时页面通过 `target="_blank"` 点击公开 `https://example.org/`，实际交给系统 Chrome，标题为 `Example Domain`；桌面工作区保持本机 URL。验收标签已关闭。

这些结果证明桌面容器与隔离模拟服务的连接、Cookie、同源回调、恢复、下载及前端绘制路径，不能替代完整 BidOps 业务验收。尚未完成的原生验收包括真实业务审核包内容、企业 IdP/SSO、真实采购站的登录/下载行为、下载过程中关窗的各系统行为、Intel Mac/Windows/Linux、跨机器分发和用户人工验收。窗口关闭后会阻止新的下载结果提示，但没有据此声明所有关闭时序均已原生覆盖。临时服务与验收应用均已停止。

现有 `scripts/check_demo_browser.sh` 与 `frontend/scripts/demo-live.mjs` 会产生真实 DeepSeek 请求，不属于本模块默认测试。真实业务数据、模型结果、企业登录、人工验收和发布另按各自授权验证。
